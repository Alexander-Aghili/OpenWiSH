OpenWiSH · harness design review · 4 November 2026

OpenWiSH Harness Proposals

Seventeen changes to the OpenWiSH harness, ranked by what our own runs exposed. Each proposal names the failure it fixes, the literature behind it, and what it costs. The landscape section lists the projects closest to OpenWiSH and what to borrow from each.

Built from two literature sweeps (agentic interpretability, model editing and unlearning evaluation, agent evaluation integrity) and a GitHub check of every project's stars and last push on 4 November 2026. Claims the sweeps could not confirm carry an unverified mark.

The four findings behind these proposals

(a) Agents stop early79.0 % vs 61.3 %

AgenticInterpBench, Claude Sonnet 4.6, same access. HyVE forces observe, hypothesise and validate per component. In OpenWiSH, Sonnet answered 59 of 84 cases after one Python run.

(b) Agents game the metric103.8, then 9.22

MoE unlearning. The first score rewarded breaking everything, code a bit more. The fixed score passed an edit that turned two experts into a trap for all technical text. The novels-only retain set missed it.

(c) Budgets confound comparisons2 to 4 turns

WSPBench B and C cap input at 160,000 tokens. The weights payload alone holds 33,000 to 66,000, so tool conditions run out before submitting. Part of our win is budget design.

(d) Verification leaks7 audit failures

Agents computed attention or gates by hand in Python instead of calling the probe. Once, the auditor brief's generic "no search" rule overrode a task's explicit permission to fit.

Proposals, grouped by the finding they fix

Make agents investigate · finding (a)

1A falsification loop per component

Building now
Idea
A task can declare a protocol: for each component, observe, state a hypothesis, test it with an ablation or patch, and record whether the test supports it. A refuted hypothesis goes back to the hypothesis step. OpenWiSH runs this as its own labelled condition, so open-ended and scaffolded results never pool.
Why
The 17.7-point HyVE gap comes from investigation depth, not access. Our agent had the same probe and used it 38 times across 84 cases. A protocol makes the probe budget get spent where the answer is decided.
Drawbacks
HyVE's authors report most failures inside the validation step: weak plans, code errors, unresolved hypotheses. A protocol does not fix bad test code. It also hard-codes one research workflow, which suits tagging tasks better than open discovery.
Status
Tested on 16 pre-registered dev cases (seed 2026), 37 components. Prompt only 59.5 %. Open-ended probe 54.1 %. Protocol version 1 59.5 % with six times the investigation. Version 2 adds a tag-deciding test (count upstream sources for an MLP, pattern shape for a head) and scores 67.6 %. Version 2 is frozen and running on the 68 held-out cases.

Sources: HyVE, Findings of EMNLP 2026, arXiv 2606.24026. POPPER, ICML 2025, arXiv 2502.09858 (sequential falsification with e-values).

2Evidence-gated answers

Building now
Idea
Every claim in the final answer cites the probe call that tested it. A host-side check refuses the answer unless each cited call exists, finished, and ablated or patched the component it claims to test.
Why
One check covers two findings. An answer given after one run has nothing to cite (a). A result simulated by hand in Python has no probe ID, so it cannot stand in as causal evidence (d). The check reads only the run's own request records and never grades the answer.
Drawbacks
An agent can cite a real probe whose output does not support the claim. The check confirms the test happened, not that it was a good test. Semantic support checks would need an LLM judge, with its own errors.

Sources: Kosmos, Edison Scientific 2025, arXiv 2511.02824 (every statement traced to code). Agent-as-a-Judge, ICML 2025, arXiv 2410.10934 (about 90 % agreement with humans against about 70 % for LLM-as-a-judge unverified figure).

3Pre-registered predictions in the ledger

Next
Idea
Before each probe call the agent writes a structured prediction with a numeric threshold, for example "zeroing L3H2 drops accuracy by more than 30 %". The prediction is hashed into the ledger before the probe runs. Reports count confirmed, refuted and unregistered probes.
Why
Commitment before seeing results turns probing into testing (a). The auditor gets a concrete claim to check per code run (d). The hashed ledger already exists, so the cost is one record type.
Drawbacks
Agents register vague predictions unless the schema forces a number and a direction. Extra tokens per probe.

Sources: Vaccaro, "Preregister Experiments with AI Agents", ICML 2026, arXiv 2606.11217 unverified, abstract only. Luo, Kasirzadeh and Shah, NeurIPS 2025, arXiv 2509.08713 (post-hoc selection in AI-scientist systems).

4A live status board in every turn

Next
Idea
Each tool reply ends with a short board: probes and Python runs used and left, turns left, and for protocol tasks the components still lacking a tested hypothesis. A persistent notes file holds one row per component and survives context handoffs.
Why
Sonnet finished with most of its 60-run budget unspent and several components untested (a). A visible board makes that state hard to overlook, and makes spend comparable across tool setups (c).
Drawbacks
Agents may spend budget because it is there, which inflates cost without raising accuracy. Measure accuracy per probe, not only accuracy.

Sources: BATS, budget-aware tool use, 2025, arXiv 2511.17006 (ReAct accuracy with 40.4 % fewer search calls unverified figure). Anthropic, Effective context engineering for AI agents, 2025.

5An experiment library on top of the probe

Next
Idea
Ship tested helpers for the standard experiments (ablate, patch, interchange, attention summary, logit attribution) that return compact summaries, validate calls before running them, and cap large outputs with a request to narrow the query.
Why
Agents simulate the network by hand when the probe feels awkward (d), and investigations fail on their own test code (a). SWE-agent found interface details, such as a linter on edits and summarised search, mattered more than prompting.
Drawbacks
A curated library encodes our priors about which experiments matter. Summaries can hide the anomaly that would have mattered. Keep raw arrays one call away.

Sources: MAIA, arXiv 2404.14394. SWE-agent, NeurIPS 2024, arXiv 2405.15793. Beel et al., SIGIR Forum 2025, arXiv 2502.14297 (42 % of AI Scientist experiments failed, mostly on code errors).

Score honestly · finding (b)

6Conjunctive multi-axis edit scores with adjacent retain sets

Next
Idea
Score every write task on separate axes, as model editing does: efficacy on the target, generalisation to paraphrases, specificity on everything else (including a KL measure). Pass only when every axis clears its threshold. Draw retain sets from domains next to the target, keep them hidden, and rotate them.
Why
Both MoE failures came from the score. A difference score rewarded breaking everything. A novels-only retain set passed an edit that broke C, Markdown and docs. WMDP measures retained utility on subjects next to the forgotten one for this reason.
Drawbacks
More evaluation compute per run. Agents hunt for regions the metrics leave out, so coverage never ends. Thresholds are judgment calls, and moving them after seeing results needs disclosure.
Status
Done as MoE task version 3: technical English joins the retain set, and the score rewards forgetting over breaking. Every fixed baseline and the earlier two-expert trap now score 0. Sol's best edit (Python +0.52, prose +0.06) misses the technical-English limit by 0.002 nats, so it scores 0 too.

Sources: ROME and CounterFact, arXiv 2202.05262. MEMIT, arXiv 2210.07229. AlphaEdit, ICLR 2025, arXiv 2410.02355. CounterFact+, Findings of ACL 2023, arXiv 2305.17553. WMDP, arXiv 2403.03218. MUSE, ICLR 2025, arXiv 2407.06460. TOFU, arXiv 2401.06121.

7An Agentic Benchmark Checklist pass on every task

Next
Idea
Before a task ships, run the ABC checks for task validity, outcome validity and reporting, and record the answers in the task folder.
Why
The checklist asks whether a degenerate strategy scores well. That question would have caught MoE score version 1 before any agent ran. ABC found outcome-validity problems in 7 of 10 widely used agent benchmarks.
Drawbacks
Process overhead per task, and a checklist only catches the failure modes it names.

Source: Zhu et al., NeurIPS 2025 Datasets and Benchmarks, arXiv 2507.02825.

8An adversarial removal check in the scorer

Careful
Idea
After scoring an unlearning edit, the host tries to undo the edit: a short relearning run on half the forget set, measured on the other half, plus direction removal. The report separates removed from hidden.
Why
The two-expert trap looks like obfuscation, not removal. Published unlearning methods often recover most of the erased skill after fine-tuning on a handful of unrelated examples.
Drawbacks
The fine-tuning runs on the host, never by the agent, but readers may read it as breaking the no-optimisation rule. It needs clear documentation and compute per scored run.

Sources: Łucki et al., TMLR 2025, arXiv 2409.18025. Fan et al., ICML 2025, arXiv 2502.05374.

9Impossible-task canaries

Later
Idea
Add task variants with no honest solution. Any success on them measures an agent's tendency to game, reported per model next to its scores.
Why
Gaming in finding (b) stayed within the rules, so audits alone will not surface it. METR saw o3 reward-hack in 30.4 % of RE-Bench runs, and asking the model not to cheat barely helped. The fix has to live in the environment.
Drawbacks
Costs runs that score nothing, and designing a truly impossible weight-editing task is hard. A clever honest edit could look like a cheat.

Sources: ImpossibleBench, ICLR 2026, arXiv 2510.20270. METR, Recent reward hacking, 2025. AI Scientist, arXiv 2408.06292 (edited its own timeout).

10A hidden test metric with a separate dev metric

Careful
Idea
Show the agent a dev metric on practice data and keep the test metric's exact form hidden.
Why
Reward hacking rises when the full scoring function is visible. Our MoE prompt printed the exact formula, and the agent optimised the formula.
Drawbacks
Agents check their own work less well, and the task becomes harder to reproduce from the prompt alone. Today OpenWiSH states every score in the prompt, which keeps runs transparent. Decide per task.

Source: METR, Recent reward hacking, 2025.

Compare fairly · finding (c)

11Cost-accuracy reporting and pre-specified budget sweeps

Next
Idea
Log tokens, turns, probe calls and dollars for every run, and plot accuracy against cost. Before comparing two tool setups, fix a set of budgets that includes each setup's native budget, and run both at each.
Why
Our WSPBench win mixes tool design with a budget that left WSPBench's own conditions 2 to 4 turns. A sweep separates the two. AxBench found plain prompting beat every steering method tested, which shows how cheap baselines reorder rankings.
Drawbacks
Sweeps multiply cost, and conflict with the CPU budget on local runs. Probe compute and LLM tokens have no common unit.

Sources: Kapoor et al., "AI Agents That Matter", arXiv 2407.01502. HAL, ICLR 2026, arXiv 2510.11977. AxBench, ICML 2025, arXiv 2501.17148.

12Three controls in every environment

Next
Idea
Each environment ships a no-weights control (prompt only), a no-numbers control (the edit described without the weights), and a scripted or closed-form solver (for edits, a ROME or AlphaEdit-style baseline).
Why
Our prompt-only control showed most AgenticInterpBench signal comes from the task text. A no-numbers control found reading Qwen weights adds only +0.06 correlation with measured effects. Without controls, "the agent read the weights" stays an untested claim.
Drawbacks
Two to three extra runs per environment. Closed-form editors use gradients for some steps, so they serve as reference points, never as OpenWiSH agents.

Sources: csinva/weight-space-programming-autoresearch (no-numbers control). WSPBench scripted solver, alexcarterhq/wspbench. EasyEdit, zjunlp/EasyEdit.

13Repeats, and several investigators within one budget

Later
Idea
Run every headline condition at least three times and report spread. Optionally split one budget across several independent investigators and aggregate their answers.
Why
Nearly every number on our results page is one attempt. Anthropic's auditing work reports a single investigator at 13 % and an aggregate of several at 42 %, so aggregation is a cheap lever, as long as the budget counts all of it.
Drawbacks
Repeats triple the cost of a result. Aggregation that escapes the budget reopens the fairness problem in (c).

Source: Anthropic, Building and evaluating alignment auditing agents, 2025 13 % and 42 % from summaries.

Verify claims · finding (d)

14Task rules above the auditor brief

Next
Idea
Rank instructions explicitly: the task's rules first, the generic auditor brief second. Each verdict quotes the task rule it enforces. Keep a regression set of labelled allowed and disallowed transcripts, and re-audit published runs when the brief changes, showing old and new verdicts side by side.
Why
The exp3 run failed audit for an annealing fit the task explicitly allowed, because the brief banned search everywhere. The brief served weight-editing tasks and misfired on a read task.
Drawbacks
The auditor reads text the agent wrote, so it stays open to prompt injection from transcripts. A regression set needs ongoing labelling.
Status
Done. Task rules now take precedence, and exp3 re-audits as valid, with the old verdict kept beside the new one. The auditor also sees every probe call as context now. Without that, all five failed audits in the first protocol dev run were false positives.

Sources: Wallace et al., "The Instruction Hierarchy", arXiv 2404.13208. Greenblatt et al., AI Control, arXiv 2312.06942.

15A static detector for hand-simulated forward passes

Next
Idea
Flag code that chains matrix products and nonlinearities across several layers' weights on input-shaped arrays. Under access levels without probes, block it. With probes, charge it against the probe budget.
Why
Seven runs today failed audit for exactly this. A programmatic first line of defence costs nothing per run and leaves the LLM auditor for the subtle cases.
Drawbacks
False positives on legitimate weight analysis such as OV and QK circuits, which also multiply weights. Our own proposal, so it needs tuning on labelled transcripts first.

Basis: OpenAI chain-of-thought monitoring, arXiv 2503.11926 (optimising against a monitor causes obfuscation, so never train against this detector).

16Causal-faithfulness scores for read tasks

Later
Idea
Beyond matching a label, score an explanation by interchange intervention accuracy, and test that the claimed circuit preserves, localises and minimally contains the mechanism.
Why
A correct tag can come from the task text, as our prompt-only control showed. A causal score requires the explanation to predict interventions, which the task text cannot supply.
Drawbacks
Compute per scored run, and ground truth exists only for synthetic circuits.

Sources: MIB, ICML 2025, arXiv 2504.13151. Shi et al., NeurIPS 2024, arXiv 2410.13032.

Reach researchers where they work

17Inspect adapter, MCP server and standard probe backends

Later
Idea
Export OpenWiSH environments as Inspect tasks. Expose the kernel, probes and gate as an MCP server, as OpenWSP does. Offer nnsight intervention graphs or TransformerLens hooks as probe backends, and feed run folders to Docent for transcript search.
Why
Inspect (3,166 stars) is where evaluators work, and METR is moving to it. TransformerLens (4,036 stars) and nnsight (1,139 stars) are what interpretability researchers already use. Meeting them there costs less than asking them to learn a new tool.
Drawbacks
Maintenance across fast-moving dependencies. An MCP surface must keep the gate and the ledger as the only write path.

Sources: inspect_ai, nnsight, TransformerLens, Docent, OpenWSP.

Deferred: human expert baselines (high cost, no budget yet) and trained investigator agents (they fall under the no-optimisation rule only if training stays outside the harness).

The closest projects

Weight-space programming is days old. No project combines a gated, ledgered edit path, an auditor, budgeted probes and environments across RL policies, Go, language-model edits, MoE unlearning and interpretability benchmarks. The likeliest main competitor is the Sparks authors' own harness, announced and not yet released. Stars and last push checked on GitHub, 4 November 2026.
