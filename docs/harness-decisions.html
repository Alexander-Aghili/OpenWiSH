OpenWiSH · Open Weight-Space Harness

OpenWiSH Design Decisions

OpenWiSH is an open-source harness for weight-space programming: an agent reads, reasons about and writes the weights of neural networks directly. It works with any model or agent you plug in, has explicit Read, Write and Harness layers, and ships with environments to work in. The aim is the capability of a state-of-the-art coding harness, applied to weights instead of source code. It was inspired by Sparks of Weight-Space Programming (Takehi, Teoh, Zhang, Khattab, MIT CSAIL, 2026), which found that frontier models can read and write weights and that harnesses are a main bottleneck. Amber cards are your decisions; blue cards are calls I made while building it.

The three layers

Each layer answers one question and has a narrow interface. Tasks and agents only touch the interfaces, so each layer can be improved or swapped on its own.

Read

What is in this network, and what does it do?

load(name) · NAMES · render (decimals | int×scale) forward tools: games · positions · attention (counted, validated, charged on success)
  • Weights as arrays, never as a runnable model
  • Weights as text for no-tool reading (the authors' formats)
  • Behaviour only through budgeted probes the task declares
openwish-tensor · openwish-sandbox · task forward adapters

Write

save_edit · drop_edit · checkpoint · restore · edits() ```edits language: W1[3:600:60, 0] = [...] ops: assign · replace · add_rank1 · project_out · revert
  • One Rust gate with a per-task policy
  • Append-only ledger: op, reason, entries changed, before/after hashes
  • Portable edit sets that apply onto a base, with hash checks

Harness

How does any agent work here for hours, safely and measurably?

  • Agent loop, budgets and shared pools, nudges
  • Context handoff, retries, refusals handled, crash-resume
  • Sandbox, static checks and auditor; environments as TOML tasks
openwish-core · -llm · -sandbox · -audit · -envs · -cli

How a run works

Edit, don't optimise: how the Write layer is protected

Agents may compute an edit with code. They may not reach the weights through gradients, optimisers, fitting to data, search, or running the network outside the declared probes. No single layer is airtight, so results report the audit status next to the score.

1 · hard

Capability removal

The kernel gets arrays, never a runnable model. backward, autograd.grad, torch.optim and requires_grad_(True) raise. There's no network or GPU, and hidden assets are never mounted.

2 · hard

Edit gate

Per-task policy: allowed and forbidden tensors, no whole-tensor constant scaling, a maximum fraction changed, finite values only. Refused edits leave no trace in the ledger.

3 · soft

Static checks

Every code run is scanned for backprop, optimisers, scipy.optimize, gradient steps, fitting or least squares fed into save_edit, and forward passes. These are flagged, not blocked.

4 · soft

Auditor review

openwish audit sends every code run, with the rules text the agent saw, to a reviewer model. One verdict of violation marks the run invalid.

Environments and benchmarks

Bundled today

  • Read: game policy MLPs, diffusion MLPs, char-level transformers (middle blocks only), sycophantic vs honest Gemma 3 270M pairs
  • Fix: a failing Kinetix car policy, edited in one reply
  • Write from zero: MinAtar Breakout, Seaquest and Asterix policies; a 1.48M-weight 9x9 Go policy with games and positions probes

These follow the blog's experiments, and each ships with its scorer.

Candidates to add

  • Known ground truth: Tracr-compiled transformers, InterpBench, AdderBoard
  • Model zoos: Schürholt et al. 2021, Unterthiner et al. 2020, NWS, Implicit-Zoo, LoRA-WS (predict accuracy or hyperparameters from weights)
  • Editing with locality: CounterFact and zsRE
  • Auditing: TrojAI backdoored models
  • Control: more Kinetix levels and all MinAtar games

Showing that the harness helps

The harness can't make a model smarter. It can stop wasting the agent's budget and context, give it better instruments, and make results trustworthy. To measure that, run the same agent and model on the same environments in two modes. A baseline mode replays the original protocol: verbatim prompts, one block per turn, fixed 40-turn handoffs, no notebook, no checkpoints. The full OpenWiSH mode has every feature on. Then compare score, budget wasted on failed requests, turns to finish, completion and audit validity, over three or more repeats per condition.

The best testbed is Go, where score climbs with the number of passes (0, 10, 25, 50), so instrument quality shows up directly. Next best are char-LM reading (copying-head recall) and MinAtar writing.
